# Corporate-Branded SOW

Use this skill to produce production-ready SOW documents that are commercially clear, legally cautious, and consistent with enterprise writing standards.

## Gather Required Inputs First

Collect or confirm:

1. Client legal entity and project name
2. Business outcomes and measurable success criteria
3. In-scope and out-of-scope boundaries
4. Deliverables and acceptance criteria
5. Timeline, milestones, dependencies, and constraints
6. Roles and governance (client and provider)
7. Pricing model, payment schedule, and assumptions
8. Change control approach
9. Legal/risk requirements (IP, confidentiality, liability, data handling)

If any item is missing, produce an assumptions block and mark unresolved items as `TBD`.

## Follow This Workflow

1. Open `references/sow-structure.md` and map user input to each required section.
2. Draft using `assets/sow-template.md` section-by-section.
3. Apply style constraints from `references/brand-voice.md`.
4. Run quality checks in `references/review-checklist.md`.
5. Output:
   - A complete SOW draft
   - A short list of open decisions
   - A concise redline-style summary of key changes when revising existing SOWs

## Drafting Rules

- Use explicit scope boundaries and avoid ambiguous terms like "as needed" without limits.
- Write measurable acceptance criteria for every deliverable.
- Keep commercial language internally consistent (rates, units, invoices, taxes, currency).
- State assumptions separately from obligations.
- Use neutral, professional tone and active voice.
- Flag high-risk clauses with `RISK NOTE:` for legal review.

## Output Format

Provide output in this order:

1. `SOW Draft`
2. `Open Items / Client Decisions`
3. `Risk Notes for Legal Review`

Keep headings and numbering stable so downstream document automation can parse the draft.
